# 07 Text engine
Typed text is Markdown, laid out on the page grid so that every line sits on the template's rules, for every font, with inline LaTeX, at every zoom level. Module `core:text` (layout, parsing, fonts, math) + `feature:editor` (editing UI).

## Grid unit
- U (points) comes from the page template (05-canvas-rendering.md#templates): rule spacing, grid cell, dot spacing, or the blank/custom default.
- Grid origin: y0 = template `marginTopPt`; rule lines at y0 + n*U. Horizontal grid columns (grid/dotted/graph templates) at x0 + m*U; lined templates have no column snapping except the margin line.
- `GridUnit.of(template)` is the single source for U and the grid origin. Changing the template spacing re-flows text on that page (line counts change, content never overlaps).
- `GridUnit` lives in core:model (used by core:text and core:render). Only LINED/GRID/DOTTED read `spacingPt` (CUSTOM reads `customGridPt`); other kinds use the fixed U of the table. Invalid decoded values (NaN, <= 0) fall back to the kind default, U is clamped to 2..50 mm, margins to 0..A3 height (A-018).

## Line box
- Every text line occupies a line box of height k*U (k = 1 for body text, 2 for H1/H2). Line boxes are stacked without gaps; paragraph gaps are whole empty lines.
- The baseline of a line is on the rule at the bottom of its line box, raised by the flow's lift. Descenders extend below the baseline, at lift 0 into the next box (like handwriting on ruled paper).
- Baseline lift (A-054, R-TXT-03, R-TXT-05): `FlowStyle.baselineLiftUnits` / `FlowTextStyle.baselineLiftUnits`, 0..0.35 U in 0.05 U steps, default 0. Every baseline of the flow (text, list markers, task checkboxes, table cells, inline math, empty lines) sits lift x U above its rule; line box heights and block heights do not change. Block math stays centered in its line boxes. The live field follows because it aligns to `BlockLayout.baselinePt`. The Text panel's "Distance above lines" slider sets the lift of flows the tool creates next (A-051).
- Implementation: Compose text with `TextStyle(lineHeight = k*U, lineHeightStyle = LineHeightStyle(Alignment.Bottom, Trim.None))`. The renderer shifts the block by `baselineCorrection = k*U*r - firstLineBaseline`, measured from the layout result (in reference px), so baselines land exactly on rules. No placement decision uses the font's ascent or descent (A-006: a descent-based shift missed rules by up to 10 px).
- Layout happens at a fixed reference scale r = round(4*U)/U px per pt (about 4; chosen so one grid unit is a whole number of px, because Compose rounds line heights up to whole px and every non-integer pitch drifts per line) with linear (unhinted, subpixel) glyph metrics, so line breaks do not change with zoom. Drawing scales the canvas by scale / r.
- Invariant (tested): for every line, |baselineY - (y0 + n*U - lift*U)| <= 0.5 px at zoom 1, 2, 4 (lift 0, 0.15 and 0.35 U), and every line box height is an integer multiple of U.

## Font normalization
- Fonts differ in em-box proportions. Size is therefore derived, not chosen in sp: `sizePx = targetCapHeight / capRatio(typeface)` where `capRatio` = cap height ("H" bounds) / size, measured once per typeface and cached in `FontMetricsCache`.
- Target cap heights (fraction of U): body S 0.38, M 0.45 (default), L 0.52; H1 0.95 (2U box); H2 0.75 (2U box); H3 0.55 bold (1U box); code 0.40 (monospace); table cells = body; sticky notes = body.
- The user picks S/M/L per flow and a font family per flow. Mixed fonts inside a flow: code spans use the monospace family, math uses the math renderer; all share the line box.
- Free size (A-039): the flow's body cap fraction may also be any value in 0.30..1.80; every role scales by body/0.45 and its line box is max(role minimum, ceil(cap / 0.66)) x U (the table above is the M case: H1/H2 minimum 2U, others 1U). Text never moves inside its box: baselines stay on rules.
- Bold roles (H1..H3) are sized from the bold face's own cap ratio. `TextSizing.derive` returns font size, cap fraction and box units; tests assert the cap height within 1% for all bundled fonts.

## Fonts
Bundled (OFL, downloaded from github.com/google/fonts in P01-S3, licenses shipped in assets/licenses): regular, italic, bold, bold italic where available; variable fonts where Google publishes them.
| Group | Families |
|---|---|
| Sans | Inter, IBM Plex Sans, Source Sans 3, Nunito, Lexend, Atkinson Hyperlegible Next (or Atkinson Hyperlegible), Noto Sans |
| Serif | Source Serif 4, Lora, Merriweather, EB Garamond, Crimson Pro, Literata |
| Mono | JetBrains Mono, IBM Plex Mono |
| Handwriting | Caveat, Patrick Hand, Kalam, Architects Daughter, Shadows Into Light |
Default text font: Inter. Custom fonts: import `.ttf/.otf` via the system file picker; copied to app storage and mirrored into the library folder `.fonts/` so other devices can install them; documents reference fonts by family name with fallback to Inter. UI fonts (Inter, Literata) live separately in core:designsystem.
- `FontRegistry` = bundled families + imported ones (`CustomFontStore`: family and face read from the OpenType `name` table, files `fonts/<family>-<face>.ttf|otf` in app files, mirrored to library `.fonts/`, `syncFromLibrary` installs fonts found there; max 32 MB, collections rejected). Bundled names win on a clash.
- As built (A-051): `FontLibrary` (core:text, singleton) publishes the current `FontRegistry`; `BlockLayouter` reads it through a provider and drops its cached layouts when a new registry appears. feature:editor provides `CustomFontStore` (app files + the library folder while storage access is granted); the Application syncs it once per process start off the main thread. The Text tool's font and size (row 2 and panel) are the `FlowStyle` of flows the tool creates next; existing flows keep theirs. Laid out flows refresh on their next relayout after an import.
- Fallback chain: exact family name -> same name ignoring case/spaces -> Inter. Code uses the flow family if it is monospace, else JetBrains Mono. Missing glyphs (CJK, emoji) come from the system fallback fonts.
- Variable families load each weight through `VariableResourceFont`: the platform font is built with its `wght` axis set (`android.graphics.fonts.Font.Builder`) plus the system fallback. Compose's `Font(resId, variationSettings)` drew bold at regular weight on the Pad 7 (docs/notes/gotchas.md).

## Blocks
A flow's Markdown is split into blocks. Block = the unit of parsing, layout caching, invalidation, and focused editing. Runtime block ids are stable within a session (not stored).
| Block | Line boxes |
|---|---|
| Paragraph | n x 1U (wrapped lines); empty paragraph = 1U |
| Heading 1 / 2 | n x 2U |
| Heading 3 | n x 1U, bold |
| Bullet / numbered / task item | n x 1U, indent = level x indent step |
| Quote / callout | n x 1U, left bar, callout icon line for `> [!NOTE]` style |
| Code block | n x 1U, monospace, muted background, no wrapping beyond frame (soft wrap on) |
| Math block | ceil(height / U) x 1U, unsplittable |
| Table | rows x (max cell lines x U), splittable between rows |
| Horizontal rule | 1U, line drawn at the box center |
Indent step: 1 grid column on grid/dotted templates, 6 mm on lined/blank.

### Block layout
- `BlockLayouter.layout(block, widthPt, FlowTextStyle, LayoutGrid)` returns a `BlockLayout` (line count, box units, baselines and line tops in pt from the block's top-left, text and marker left edges, `BlockDecoration`). Results are cached (LRU, 2048 entries) by block source text, width, flow style (family, body cap, alignment, palette) and grid (U, indent step); block ids are not part of the key. Uncached layouts are traced as `text:layout`.
- Lists (A-040): the marker gutter of a level-n item starts at n x step (at most half the width), the text at (n+1) x step. Bullets are centered in the gutter, numbers end-aligned 0.25U before the text; the marker is laid out on one line on the item's first baseline. Task items draw no marker: a 0.7U checkbox in the gutter whose bottom sits on the first baseline.
- Quote: text at 1 step, bar 0.12U wide at 0.25 step. Callout: a bold title line ("Note", "Tip", "Warning", ...) above the body; the renderer adds the icon from `QuoteBar.callout`. Code: insets of 0.5U left and right, background over the whole block. Empty paragraph and rule: one body line box, rule at its center.
- Alignment applies to paragraphs (start, center, justified) and headings (start, center); lists, quotes, code and tables stay start-aligned.
- Tables: see #tables-as-built. Math: see #math-as-built.
- Regression suite (`src/sharedTest`, runs on Robolectric and on the tablet): 20 fonts x every block style x body S/M/L/1.2 x lined and graph grids; baselines are measured from the glyph runs actually drawn onto a recording canvas at zoom 1, 2 and 4 on the Pad 7 fit-width scale.

## Markdown dialect
- CommonMark + GFM tables, strikethrough (`~~`), task lists (`- [ ]`, `- [x]`), GFM alerts for callouts (`> [!NOTE]`, `[!TIP]`, `[!WARNING]`).
- Folio inline extensions: `==highlight==`, inline math `$...$` (not preceded by a digit, to keep "$5" literal; `\$` escapes), block math `$$` on its own lines, links to notes stored as `[Title](folio://doc/<uuid>)` (the `[[` shortcut in the editor inserts them).
- Enter creates a new block; Shift+Enter inserts a hard line break (stored as trailing backslash).
- Block splitting (`core/text/.../markdown`): each list item, heading, rule, fenced code, `$$` math and table is its own block; paragraph/quote/item continuation lines stay in the block. One blank line between blocks is the plain separator (kept as the block's `gap`); each further blank line is an empty paragraph block (1U). List level = leading spaces / 2.
- Serialization must be lossless for everything Folio produces (round-trip tests). Foreign Markdown opens as-is; unknown syntax renders as text.

## Block styles
- Bold, italic, strikethrough, inline code (monospace, muted background), highlight (yellow background band inside the line box), links (accent color, underline), inline math.
- Lists: bullets per level (disc, circle, dash); numbers per level (1., a., i.); task checkboxes 0.7U square, tap toggles.
- Headings: display weight of the chosen family; H1/H2 have 2U boxes so their baselines sit on every second rule.
- Alignment per flow: start (default), center, justified (paragraphs only).

### Block styles (as built)
- List levels follow leading spaces / 2 (Tab writes 2 spaces), so `1.` > `a.` > `i.` and disc > circle > dash cycle by level.
- Links: web links and note links (`folio://doc/`, `[[Title]]`) share the accent color and underline. A note link whose target the index does not know (missing or in the bin) is drawn muted gray and struck through (`FlowTextStyle.brokenLinks`, A-049). The layout cache key holds only the broken ids the block itself links to, so a change in the set re-lays out just the blocks that link to those ids.
- Taps (`FlowLayout.tapTargetAt`): a finger tap on a block that is not being edited acts on what is under it before it focuses: the task checkbox (anywhere in the item's marker gutter on its first line) toggles `[ ]`/`[x]` through `Formatting.toggleTask` without focusing; a web link opens via ACTION_VIEW; a note link opens that note (a `[[Title]]` link opens the note with exactly that title). Taps in the focused field only move the caret. Links in table cells are not tappable yet. In read mode (navigate tool) links and checkboxes still act, for a finger and for a pen tap (10-editor-ui.md#read-mode); neither places a caret there.
- Taps as built: `CanvasHostView.onFingerTap` asks `TextController.tapAt` first (in every tool); `TextEditor` queues a checkbox toggle like an edit (one undo step, no focus) and emits link targets on `linkTaps`, which the ViewModel turns into editor events. The `[[` query (`TextController.noteQuery`) follows typed text only while the caret stays at its end; any other edit, caret move, selection, cell change or blur ends it. While a query is open, row 2 shows the picker ("Link to" plus matching titles, "No matching notes" when none) instead of the formatting bar; in a left or right dock it is a 160 dp card whose titles wrap.

## Flows and frames
- **Body flow:** one per document, created on first typed text in a page body. Its frames are the BODY frames of pages in document order.
- **Body frame rect** = the template's text zone: lined/blank: left margin (25 mm margin line + 2 mm, or 12 mm without margin line) to width - 12 mm, top y0, bottom = last rule above height - 12 mm. Grid/dotted/graph: 12 mm margins snapped to grid columns. Cornell: notes column (cue column and summary are separate BOX frames created on tap). Planners: notes areas. Infinite pages: origin width, unbounded height.
- **Distribution:** block line boxes are placed sequentially into frames. Paragraphs, lists, quotes, code split at line boundaries; tables between rows; math blocks, rules, and headings never split (a heading is also kept with the next line). Paragraph gap setting inserts 0 or 1 empty line between blocks.
- **Auto-continue:** when the last frame overflows on a fixed page, a new page with the same spec/background is inserted directly after that page and gets a BODY frame (a "continuation page"). If text shrinks, continuation pages that end up with no text and no other objects are removed. Both are part of the same undo step as the edit.
- **Free text boxes (BOX):** own flow per box. Top snaps to a rule line; left snaps to a grid column (grid templates) or is free (lined) when created; width default 60% of body width, min 20 mm; height grows in whole U steps. Resizable and movable via selection.
- As built (A-055, P06-T17): a focused box shows an outline, a top grip and left/right width handles (`BoxHandles` in the canvas host). Dragging the grip (finger or pen) moves the box, also onto another page; a handle moves that edge. On release the top sits on the nearest rule and the edges on the nearest grid column (whole millimeters on pages without columns), inside the page; `EditorText.boxCommand` places the frame and reflows its flow as one undo step. The pen over a handle keeps the box focused.
- As built (A-055 amended, P07-T13, spec 10-editor-ui.md#text-boxes): the selected box is `EditorText`'s box (Preview) or its focused flow (Edit); `BoxModes.next` is the pure state machine (tap, caret tap, Edit button, Back, pen over, box gone) and `TextSnapshot.box` / `CanvasText.box` (`SelectedBox`: one `BoxPiece` per frame, its text column and outline; the body flow is not movable) feed the canvas. Back and Escape go through `EditorViewModel.boxBack`; with the soft keyboard up the keyboard takes Back, so `LiveTextField.onKeyboardHidden` (the window's IME insets after a layout) blurs the field instead (A-060). `BoxHandles` (canvas overlay) draws a 1.5 dp accent outline on every piece, the grip and knobs on the first one and the `BoxToolbar` pill (Edit, Delete; Color, Size, Alignment, Fill laid out but hidden until T15 to T17), above the box, below it without room, clamped to the view. A drag on the grip, or inside a box in Preview (a finger, or the pen with the Text tool), moves it: `TextZones.movedBox` keeps x where dragged (inside the box zone) and puts the top on a rule in whole U; the tiles leave the box's runs out (`PageText.without`) while the overlay draws them at the drag, then until the tiles under the landed box are drawn (at most 300 ms). On release `EditorText.moveBoxCommand` moves the first frame (also to another page), shifts the other frames and the `FlowBox` anchor and borders by dx, clears the vertical offset, drops continuation frames and reflows: one undo step; a refused move clears the preview. A grip drag or pen down on the grip or a knob of a box in Edit drops it to Preview first (D-041). `deleteBoxCommand` removes the frames, the emptied continuation pages and the flow as one undo step. The knobs still snap (P06-T17) until T15.
- As built (A-059, P07-T12): every flow is a box (`FlowBox` on `TextFlow`); frames hold the text column per page. The outline and hit area of a frame is that column padded 0.5 U left and right, as tall as its used lines (at least one), plus the editor's slop, so a tap below the body text misses the body flow. A Text tool tap outside every box makes an auto width box (`TextZones.newBoxAt`) on the line holding the tap, anchored at the tap; `FlowReflow` sets its borders to its widest line (`TextZones.autoBorders`: growing right for start text, left for end text, both ways for centered text, at most to the page text zone `TextZones.boxZone`, then wrapping). Boxes of auto-continuing flows (every new box) end at the zone bottom and continue on a continuation page between the same borders from the zone top. While a block of an auto width box is edited, the keystroke is laid out at the widest borders the box may take (`FrameSlot.growRect`), so a line does not wrap before the reflow widens the box, and the reflow gets the edited block (`editBlock`). With the Text tool active, `BoxOutlines` (overlay view) draws every page box outline dashed, 1 dp neutral gray, except the focused one, which shows its handles.
- **Sticky notes:** own flow; inner padding 0.5U; lines at U relative to the sticky's own top (no visible rules); rotation applies to the whole sticky.

### Flow engine
- Code: `TextZones` (core:model) computes body rects, new box rects, box growth and sticky content rects. In core:text `flow/`: `FlowDistributor` (pure placement in whole U), `FlowLayouter` (blocks to `FlowLayout`), `FlowReflow` (page changes) and `FlowSearch` (search hit to page). Slots come from loaded page bodies only, so callers load a flow's pages first.
- Each block is laid out at the width and grid of the frame it starts in. A continuation in a frame of another width keeps those line breaks.
- An unsplittable block taller than an empty frame takes that frame and hangs out of it, so distribution always ends. Infinite pages and auto-grow boxes of flows that do not continue are unbounded; auto-grow boxes of auto-continuing flows hold lines down to the text zone bottom (A-059). Infinite pages never auto-continue.
- Reflow: `FlowReflow.plan` runs on the document after the edit and returns one command, which the caller batches with the edit: `InsertPages` for continuation pages (same spec and template, no PDF page, BODY frame at the body rect or a box between the last box's borders, placed after the last frame's page), or `RemovePages` for trailing BODY frames or auto-grow boxes without text, plus `UpdateObjects` to resize auto-grow boxes to max(1, used) x U and auto width boxes to their borders. A page is only removed when it holds nothing but its frame, and the flow's first page is never removed.
- Page duplicate (D-027): each text object gets a new, independent flow. A BODY frame becomes a fixed BOX frame at the same rect that holds the blocks shown on that page (`FlowLayout.markdownOn`), so a document keeps one body flow. Boxes and sticky notes copy their whole text. Cloned flows do not auto-continue.
- Search page lookup: `FlowSearch.firstPage` returns the page of the first line showing any query term (case-insensitive substring), taking the earliest page over all flows. Text overflowing a fixed box is on no page.
- Editor wiring (A-043, feature:editor `text/`): `TextEngine` (Hilt singleton: `FlowLayouter`, `FlowReflow`) and `EditorText` per session. `EditorText` loads every page once when the document has flows (frames may sit on any page, `DocumentSession` never evicts frame pages), lays out when flows, page specs/backgrounds or frames change (not on ink commits), and publishes a `TextSnapshot` (layouts + one `PageText` per page; unchanged pages keep their instance). `EditorSession.editFlow` builds `Batch(EditFlow, FlowReflow.plan(...).command)` as one undo step; `duplicatePages` passes `FlowLayout.markdownOn`; `showSearchMatch(query)` jumps to `FlowSearch.firstPage` once the canvas host is attached. `FlowParses` keeps the parsed `MarkdownDocument` per flow so block ids survive edits.

## Rendering
- `BlockLayout` = reference-scale layout of one block for a given width + style key + U: line ranges, line box heights, placeholder rects (math, checkboxes), baseline correction. Cached (LRU, key = block text hash + width + style + U).
- `FlowLayout` = distribution result: per frame, the list of (block, first line, last line, y offset in U).
- Unfocused blocks are painted by `PageRenderer` into content tiles from `BlockLayout`s (Compose `Paragraph.paint` on the tile canvas with scale), then math and checkboxes are drawn at their placeholder rects.
- Invalidation after an edit: the edited block; if its line count changed, every following line in that frame and later frames (tile invalidation by rect).
- As built (A-042, core:text `flow/PageText.kt`, `PageTexts.kt`; core:render `TextRunPainter.kt`): `FlowLayout.runs(frame)` turns the slices of a frame into `TextRun`s (layout, first line, line count, left, top, width) and `PageTexts.of(doc, layouter)` builds one immutable `PageText` per page from the frames (sticky notes wait for P07-T05). The tile layer takes it as `TileLayer.setPage(ref, body, text)`. A run's ink bounds are its line boxes, the frame width and 0.3 line box of overhang; `PageContent` indexes a frame with those bounds, so hanging text is drawn and the tiles under it are not treated as empty. `PageRenderer` paints a frame's runs at its z-order place: decorations first (code background, quote and callout bars, a round badge with i, *, ! or x beside a callout title, rules, task checkboxes), then `BlockLayout.paint` through one `TextCanvas` per tile render (D-004), with a clip around a run that continues in another frame (the clip of a run continued from the frame before starts below the descenders of the line before it, 0.3 line box less the lift). Text color is near-black on light paper and near-white on dark paper.
- Invalidation as built: `PageText.changedBounds(old, new)` is a multiset difference of runs. Run equality compares the layout by identity and `BlockLayouter` hands out the same instance for the same block, width, style and grid, so only an edited block and the blocks an inserted or removed line shifted are listed; the old and new bounds mark tiles stale.
- Layout of blocks for newly visible pages runs on the `text` dispatcher, visible-first; never on the main thread except for the focused block.
- Edited block as built (A-058, core:text `BlockLayouter.editLayout`, `flow/EditedBlock.kt`): `PageTexts.flowLayout(..., editBlockId)` lays the focused block out as its Markdown source (`BlockLayout.editsSource`: markers in `TextPalette.marker`, math as raw source, code spans and blocks styled as usual) and paginates it with the flow. Without markers or math its line breaks equal the shown layout. `FlowLayout.editedBlock(index)` gives its runs per page; `FlowLayouter.retype(flow, index, source)` lays out a typed source and distributes it from the block's first line box (`FlowDistributor.distribute(startUnits)`), main thread only, traced `text:retype`. core:render `OverlayTextPainter` paints such runs over the tiles.

## Editing
- Exactly one live text field exists: for the focused block. It sits in the canvas overlay at the block's screen rect, uses the same TextStyle with font size scaled by the viewport (not a graphics-layer scale), and system stylus handwriting disabled.
- While focused, the block is excluded from tiles; the canvas overlay draws it from its source layout, the field only holds the IME (A-058). On unfocus the block's layout is recomputed and tiles updated.
- The focused block shows Markdown markers dimmed (the palette's marker gray since A-058) via styling only (no hidden characters, so caret mapping stays trivial). Unfocused blocks render without markers.
- Caret placement: tap (pen with Text tool, or a finger tap on a text block with any tool outside read mode, A-045) maps to (block, offset) via BlockLayout; the field receives focus in the same frame. Budget: tap to visible caret <= 50 ms (`text:caret`).
- Navigation: arrows cross block boundaries (keeping the x position); Enter splits the block (new list item continues the list); Backspace at block start merges with the previous block; Tab/Shift+Tab indent list items.
- Shortcuts at block start: `# `, `## `, `### `, `- `, `* `, `1. `, `[] ` / `- [ ] `, `> `, ` ``` `, `$$`, `---`, `| a | b |` + Enter (table).
- Selection across blocks: Shift+arrows or drag handles; copy/cut/paste as Markdown (plain text fallback for foreign paste). Built in P06-T14 (A-045, A-053): #selection-as-built.
- Formatting bar (docked above the on-screen keyboard or at the toolbar options row with a hardware keyboard): bold, italic, highlight, code, math, link, heading level, list types, checklist, table. As built it is toolbar row 2 while a block is focused (a bottom-docked toolbox slides above the keyboard); undo and redo stay in the edit pill (A-045).
- Each edit is an `EditFlow` command; typing coalesces per block within 1 s.

### Block edit logic (as built)
- `core:text` `edit/` holds pure functions from a `MarkdownDocument` and a `TextSelection` (`Caret(blockId, offset)` pairs) to an `EditResult(document, selection)`: `BlockEditing` (insert, delete, copy, paste normalizing, Enter, Shift+Enter, Backspace, Delete, indent, task shortcut, left/right across blocks), `BlockStyles` (heading/list/quote switching), `Formatting` (inline markers, table, link). `Enter`, `ListEnter`, `Backspace`, `Numbering` and `BlockSplice` are the internals.
- The live field edits one block's source; the session turns any result into one `EditFlow` by `FlowTextDiff.between(before, after)` (prefix/suffix diff, never inside a surrogate pair). Typing uses the coalesce key `type:<flow>:<block>`, structural edits use none.
- A result's blocks equal what parsing its flow text gives, because undo and a reopen re-parse. `BlockSplice` widens a `"\n"` separator to a blank line where a line break would merge two blocks, and an empty last paragraph gets a terminator of its own. A property test (6000 seeds of random edits) checks this against a re-parse.
- Enter: paragraph splits (a lone pipe row becomes a table, `` ``` `` and `$$` close at once), a list item continues the list (ordered lists renumber, an empty item outdents, then leaves the list), a quote continues as a separate quote block, a table cell moves one row down (the last row gets a new row, an empty last row ends the table; #tables-as-built), code and math take a newline until the fence is closed. Shift+Enter is a hard break (two trailing spaces), at the end of a paragraph or item it behaves as Enter.
- Backspace at a marker strips it (a list item outdents first); at block start it merges into the previous block. Text never merges into or out of code, math, tables or rules (the caret moves instead).
- An unclosed fence or `$$` stays local to its block in the editor; a re-parse (undo, reopen) lets it swallow the rest of the flow.

### Live field (as built)
- Since A-058 the field draws nothing outside tables: `EditedTextView` (overlay, under the field) draws the edited block from the `EditedBlock` of `TextFieldSpec.edited` while the field holds that source, otherwise from `TextController.retype(field text)` (cached by source), and a blinking caret (500 ms, restarted on every move, hidden while a range is selected) at `EditedBlock.caretSpot`. While the handoff masks the block only the caret shows; a block that leaves stays drawn there until the tiles have it. The field still places, measures and navigates with its own layout (Up/Down at the caret's x); `CaretKeeper` keeps the overlay's caret line in view (`EditedTextView.linePx`, on the next page for a continued paragraph). The paragraphs below follow when the reflow lands. The rest of this section describes the field as the IME connection; where it says the field draws or wraps text, read the overlay. A table cell is still drawn by the field.
- `LiveTextField` is an `EditText` in the canvas overlay, placed by `TextFieldHost` from the `TextFieldSpec` that `EditorText.field` publishes (block source, `BlockLayout`, placement of the first line box): typeface of the layout, font size and line height (box units x U) scaled by the zoom, top = baseline of line 0 minus the ascent. During a zoom it scales as a layer around its top-left corner and is restyled at the settled zoom (A-046). Its line breaks come from the platform text layout, which can wrap a long line one word apart from the page layout while focused; the page layout is used again on blur (A-045).
- A block that continues into the next frame is edited in one field at its first frame; the field overhangs that frame while focused (A-045).
- Pen over the focused block: a stylus with an ink tool hovering over the field (at the latest its stylus down) ends the editing, so the pen writes there. HyperOS otherwise takes the stylus stream over a focused editor for its own handwriting service and cancels the stroke, despite `isAutoHandwritingEnabled = false` and `EditorInfo.setStylusHandwritingEnabled(false)` (A-045, docs/notes/device.md).
- The field reports every keystroke as the whole block source (`FieldEdit.Typed`) and structural keys as `FieldEdit.Key` (Enter, Shift+Enter, Backspace at the start or in the marker, Delete at the end, Left/Right at the ends, Tab, Shift+Tab); Up/Down on the edge lines move the focus to the block above or below at the caret's x. Ctrl/Alt chords go to the editor shortcuts.
- `TextEditor` (the session's `TextController`) runs field edits one after another through `EditorSession.editText`; a waiting keystroke is replaced by the next one of the same block, structural keys and formatting keep their order. An edit always lands in the block it was typed in; it moves the focus only while the focus revision is still the one it was typed at, so a tap or an earlier split wins and no keystroke is dropped. The block edit, its Markdown diff and the reflow plan run on the `text` dispatcher (`EditorText.blockEdit`); the main thread only executes the finished command (A-056).
- Long text (A-056): the field refuses IME cursor-anchor monitoring (one-shot requests still pass), since a monitoring IME makes TextView re-measure the block's lines before every frame the field draws; the canvas AndroidView has its own graphics layer, so a caret blink or keystroke does not re-record the chrome.
- Text tool and typing with nothing focused (A-050): `CanvasHostView` turns a stylus tap with the Text tool (`StylusTap`) into `TextController.placeCaret`; `CaretPlans` (pure) plans it: `Hit` (focus like a finger tap, outlines hit with 8 dp slop), `End` (end of a block) or `NewBox` (setup commands for a new auto width box, A-059). `TextEditor` queues a `NewBox` like an edit: `EditorText.newBoxCommand` (setup and reflow in one batch), execute, wait for the layout, then focus its block. A box the editor created and that is still empty when the focus leaves it is removed without an undo step: its creation is a revocable step (`DocumentSession.executeRevocable` returns the undo entry; `revoke` undoes it only while it is still the newest, adding no redo); if other steps came after it (text typed and deleted), a recorded removal (`EditorText.emptyBoxRemoval`) runs instead. Keys that reach the screen root with nothing focused go to `typeIntoPage`; keys typed while the placement runs join it and are inserted before the field shows. After the field ends, the screen root takes the key focus back.
- Tiles to field handoff (A-052): `EditorText` publishes the page text without the focused block and the field spec in one `TextSnapshot`, and the canvas applies both in one call. `TextHandoff` masks a newly focused field (only the caret shows) until `drawsBlockOf` finds every content tile under the block fresh, then shows the field text and the tiles without it in the same frame. A block leaving the field stays on screen as a `TextGhost` picture until the tiles draw it. Either side gives way after 300 ms at the latest. Trace `text:clean` (focus until both sides agree). Known limits: tiles under one block can finish in different frames (the field waits for the last one); a blur while the field is still masked has no picture to keep; a quick move to another block replaces the picture; a split or relayout gives the block a new identity, so the handoff starts over.
- Caret in view (A-052): the chrome reports how much of the canvas bottom it covers (keyboard target height or navigation bar, plus a bottom-docked toolbox) through `CanvasHost(coveredBottomPx)`. `CaretKeeper` scrolls the viewport (150 ms) so the caret line stays 24 dp inside the uncovered band whenever the caret moves, a block gets the field, or the cover changes; pans and flings never trigger it. The scroll is limited by the viewport's pan clamp. The field is created hidden once the main thread is idle after attach, so the first focus does not build it. When the editor leaves while a block is focused, the field hides the keyboard as it detaches.
- Focus frame (A-052): the frame that first draws the caret does no keyboard work and composes no chrome. The field requests focus at once (the caret needs it) but asks for the keyboard in a post that runs after that frame; a blur before then cancels it. Row 2 keeps the formatting bar and the tool options composed and only measures, places and exposes the one in use, so a focus or a blur swaps them without a composition. Traces: `text:arrive` (tap to field shown), `text:show`, `text:focus`, `text:ime`, `text:field-draw`, `text:caret`, `text:clean`.

### Selection (as built)
- Model: a flow selection is a `TextSelection` of two `Caret`s. `TextFocus` keeps the focus end (the block in the live field, its caret) and `anchor`, the other end, which may sit in another block; `spansBlocks` tells the two apart. The field shows its own part of the selection (`TextFieldSpec.anchorOffset`), so typing, paste and delete over a selection are one `FieldEdit.Replace` that `BlockEditing.insert` applies to the whole range as one undo step. A plain caret move in the field drops an anchor in another block; an in-block selection is tracked as the anchor too, without a focus revision, so the page can draw its handles. A plain arrow key over a selection that spans blocks collapses it at the field's caret without moving; soft keyboards that replace a range (`InputConnection.replaceText`, gesture typing) replace the whole selection as typing does.
- Extending: Shift+Left/Right at the field's ends and Shift+Up/Down on its edge lines move the focus end into the neighbouring block (`TextController.extendHorizontally`, `extendTo` at the caret's x) and keep the anchor. Ctrl+A selects the focused block, a second Ctrl+A the whole flow. Selection ends never land inside a table: extending moves past it, and a table inside the range is selected whole (A-053).
- Clipboard: copy and cut of a selection over blocks put its Markdown (`BlockEditing.copy`, whole blocks keep their markers) on the clipboard as plain text; inside one block the field copies the block source. Paste takes the clipboard as text (`coerceToText`, the plain fallback for foreign content) and `BlockEditing.normalizePaste`; pasted Markdown splits into blocks (`BlockEditing.paste`: Markdown that opens with a block of its own, such as a heading or a list, after visible text of the caret's block starts a new block instead of joining that text).
- Formatting: the bar's inline actions (`SelectionEditing.toggleInline`) wrap or unwrap the selected part of each block on its own, skipping blocks without inline text, as one undo step.
- Page highlight: `EditorText` publishes `SelectionHighlight` with every `TextSnapshot`: `FlowLayout.selectionBoxes` (one `RectPt` per selected line, from `BlockLayout.plainSpanOnLine`; the edited block is included and boxed in source offsets from its source layout, A-058; only an edited table cell is left to the field; tables, math and rules are boxed whole, an empty block shows a narrow mark at its left for its line break) and `caretSpot` for both ends. `SelectionOverlay`, a view above the overlay slot of `CanvasHostView`, draws the boxes and a handle (stem on the caret line, knob under it) at each end; it redraws on viewport changes and is never part of the tiles.
- Handles: a finger that goes down within a 44 dp target around a knob drags that end (`TextController.dragSelection`, the point under the finger where it took hold), across blocks and pages; the input router never sees that gesture. The pen keeps its tool.
- Touch gestures (P07-T11): `SelectionGestures` (canvas) runs `TextTouch` (pure classifier over MotionEvents) for one-finger touches in every tool but read mode: a down on a handle is the handle's; a press held for the system long-press timeout inside the touch slop is a long-press, taken only if `TextController.selectWordAt` selects the word there (haptic tick, the router's pan or tap is canceled), and its moves extend by whole words (`extendWordsTo`: the long-pressed word stays selected, the other end jumps to the start or end of the word under the finger, across blocks and pages); a second tap within the double-tap timeout and slop selects the word at its release (no word: a normal tap). A move past the slop before the timeout is a pan, a second finger a pinch; stylus touches never select. Until P07-T13 only the block in the live field is word-selectable (`selectWordAt` refuses other blocks and tables).
- Words: `WordRanges.at(block, offset)` (core:text) takes the `BreakIterator` word segment the offset lies in or touches (else the punctuation run there; blank space selects nothing). It never splits a marker: a segment inside markers selects the span they delimit (a block marker such as `## ` itself), an end inside a marker moves to its edge, and any point inside a `$...$` formula selects the whole formula.
- Menu: after a touch selection (long-press release, double tap, handle release) `SelectionOverlay` draws a pill of Cut, Copy, Paste and Select all centered above the selected lines (below them at the view top), at a constant screen size, 44 dp high. A finger or pen press on a button runs it on release through the live field's `onTextContextMenuItem`, so the clipboard paths above apply; the pen over the menu does not end the editing. Any choice but Select all closes the menu; it also hides while a handle or long-press drags and when the selection goes.

## Math
- `MathRenderer` interface (ADR-007): `layout(latex, fontSizePx, argb, display): Outcome<MathLayout>` with `MathLayout.box = MathBox(widthPx, ascentPx, depthPx)` and `draw(canvas, x, baselineY)`; vector drawing only (works on PDF canvases). Renderer: jlatexmath-android with true TeX metrics (`setTrueValues`), box padded by 0.04 em on every side because ink (accents, vector arrows, big operators) exceeds the TeX box by up to 1.9 px at 50 px (A-007).
- Inline math: laid out at the body font size, then scaled uniformly by s = min(1, 0.78U / ascent, 0.30U / depth), s >= 0.55. The text layout gets an `AboveBaseline` placeholder of width w*s and height ascent*s (never taller than the line box); the renderer draws the formula at that position with its baseline on the line baseline, so depth hangs below like descenders. If s would drop below 0.55, render at 0.55 and show a subtle dotted underline hint "tall formula: use block math".
- Block math: font size 1.15 x body; scale to fit the frame width (min 0.6); occupies ceil((ascent + depth + 0.5U) / U) lines; formula vertically centered in that span, horizontally centered (setting: left).
- Editing: tapping a formula in the focused block shows its source; invalid LaTeX renders the source in red monospace with the parser error on long-press.
- Caches: MathBox per (latex, size, color).

### Math (as built)
- `JLatexMathRenderer` is provided by `TextModule` and passed to `BlockLayouter(math = ...)`; without a renderer (tests, tools) inline math is italic source and math blocks lay out as code. Formulas are cached per (LaTeX, size px, display), LRU 512, in `MathFormulas`; they are laid out black and `MathLayout.draw(..., argb)` recolors them to the text color (`TeXIcon.setForeground`), so the cache has no color in its key. Draw is synchronized per layout (2 render threads).
- Inline math is laid out at the font size of its role (a formula in a heading is heading size) and the fit uses the role's line box instead of U: s = min(1, 0.78 box / ascent, 0.30 box / depth), box = box units x U (U for body text). The placeholder (`AboveBaseline`, height min(ascent x s, box)) reserves the space; `BlockLayout.maths` holds a `MathPlacement` per formula with its baseline on the line's rule. A tall formula (s < 0.55) is drawn at 0.55 with a dotted underline (dots every 2 pt at the depth, half alpha).
- Block math: 1.15 x body size, scaled to the width down to 0.6 (a wider formula hangs out to the right from the left edge), ceil((h + 0.5U) / U) lines of 1U, centered both ways. Left alignment is not built (D-034). Its `BlockLayout` carries the code face and size, so the live field edits the source in monospace.
- Invalid LaTeX: the source in red monospace (`TextPalette.mathError`): an inline span, or the whole block as a code block in red. `BlockLayout.mathErrors` keeps the ranges and parser messages. Tapping a formula focuses its block and the live field shows the source; when the block holds invalid LaTeX the field shows the first parser message as its error popup (`EditText.setError`, no icon) instead of a long-press tooltip (A-047).
- Grid suite: the math corpus (inline formulas in paragraphs, headings, lists, quotes, a tall one, invalid ones, three math blocks) runs in every font; it checks each formula baseline against its rule within 0.5 px at zoom 1, 2 and 4 and the 0.78/0.30 limits.

## Tables
- GFM tables with alignment row. Column widths: proportional to the max unwrapped content width, min 12 mm, sum = frame width minus indent.
- Row height = max wrapped line count of its cells x U. Cell horizontal padding 0.4U. Text baselines on rules inside cells.
- Borders: horizontal borders on rule lines (row boundaries), vertical borders at column edges, 0.75 pt, line color of the template darkened 20%. Header row bold with a 4% tint.
- Editing: tap a cell -> cell field; Tab / Shift+Tab move between cells; Enter in the last row adds a row; a mini toolbar adds/removes rows/columns and sets alignment. Stored back as normalized GFM (padded columns).

### Tables (as built)
- Layout (`BlockLayouter.table`, `TableColumns`, `TableLayout`, A-048): cells are body text, the header bold, each in its column's alignment (none and left = start). Every column is at least its widest word and 12 mm; when the unwrapped contents fit, the width is shared in proportion to them, otherwise each column gets its least width plus a share of the rest in proportion to how much more it wants. On grid templates (indent step = U) the inner borders snap to grid columns. A row is as many body line boxes as its tallest cell; `TableLayout` keeps the column edges, the first line of every row and one grid-laid paragraph per cell, so every cell baseline sits on a rule inside its row. Inline math in cells works as in paragraphs (`MathPlacement.cell`, `MathError.cell` with offsets into the cell text).
- Distribution: a table breaks before any body row but the first, so the header always has a row under it.
- Painting (`TextRunPainter`): the header tint (text color at 4% alpha), a border on the rule at the top of every row shown and below the last, the column edges down the slice; 0.75 pt (at least one pixel) in the template line color darkened 20%. `TextRun.hiddenCell` leaves one cell to the live field.
- Edit logic (`edit/TableEditing.kt`): `TableSource` finds cells in the block source (split at unescaped pipes, outer pipes optional, the delimiter row standing for the header, missing cells empty at the row end); `TableGrid` writes the table back as normalized GFM (`| cell |` padded to the widest cell of each column, at least 3 dashes, `:--`, `:-:`, `--:` for left, center, right). `setCell`, `nextCell` (Tab; past the last cell a new row), `previousCell`, `enter`, `left`/`right` at cell edges, `addRow`/`removeRow` (not the header), `addColumn`/`removeColumn` (the last one removes the table) and `align` (the same alignment again resets it) all rewrite the whole block and put the caret in the target cell. A seeded test checks that every result parses back to the same table.
- Taps: `FlowLayout.sourceOffsetAt` maps a tap on a table to the cell under it and the character in that cell's source.
- Cell field details (P06-T19): normalized GFM pads cells with spaces, so a space at either end of a cell lives only in the field until a character follows it (the model text trimmed of spaces counts as the keystroke's echo). The field reports its selection with the new cell whenever it moves to another cell, so the table buttons act on the caret's cell even when the caret offset stays the same.
- Editor (feature:editor): with the caret in a table, `TextFieldSpec.cell` (`CellField.of`) gives the live field only that cell: its text, column box, first baseline, face (bold header) and alignment; the canvas hides just that cell. Edits name the cell by `TableCell(row, column)`, not by offsets, so a field a keystroke ahead still hits the right cell: typing sends `FieldEdit.Cell` (`TableEditing.setCell`), and keys and format actions carry the cell (Enter and Shift+Enter one row down, Tab and Shift+Tab, Left and Right across cell edges, Up and Down by row line). A cell edit that echoes the typed text keeps the field (same revision) and only moves the caret to the cell's new offset after normalization. Inline markers and links work on the cell selection (`Formatting.toggleInline` reads cell spans), and source dimming is clipped to the cell.
- Table buttons (`TextFormatRow`, `EditorUiState.textInTable`): in a table the block styles and the Table button give way to add row below, remove row, add column right, remove column, then align the caret's column left, center or right (the same alignment again resets it); the inline buttons stay.
